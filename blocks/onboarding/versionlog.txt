2026052602:
    - Removed jQuery dependency from block_onboarding.js.
        * The previous file referenced $(event.target), $(".carousel-control-*")
          and $.ajax. In Moodle 4.x jQuery is loaded via AMD/RequireJS and
          is NOT guaranteed to be on the global window when a legacy
          $PAGE->requires->js() script runs. Production hit
          "Uncaught ReferenceError: $ is not defined" inside the
          DOMContentLoaded handler.
        * Rewrote in vanilla JS:
            - $(event.target)[0] was a no-op around an already-DOM node →
              uses event.target directly.
            - $(".carousel-control-next").click(...) → querySelectorAll +
              addEventListener.
            - $.ajax(...) → fetch(...) with URLSearchParams body, keeping
              the application/x-www-form-urlencoded contract that
              optional_param() in updateprofile.php already accepts.
        * Added a defensive early-return when #avatarCarousel isn't on
          the page so this script doesn't crash on pages that load it
          but don't render the onboarding markup.
        * onboardingWwwroot() helper tries Config.wwwroot first
          (legacy global), falls back to M.cfg.wwwroot (AMD-era global),
          and finally to window.location.* — so the script keeps
          working regardless of which JS bootstrap loaded for the page.
        * Fixed an existing dead bug: avatar.getAttribute("avatar-url").value
          dereferenced .value off of a primitive string (returns
          undefined). Validator accidentally still worked because the
          subsequent === "" check evaluated to false on undefined. Now
          uses the raw getAttribute() return value.
    - No server-side change: updateprofile.php already supports both
      GET and POST via optional_param().

2026052601:
    - Portability + security sweep on the onboarding URLs:
        * block_onboarding.php "continue" buttons on the second and third
          onboarding pages no longer use the bare href '/?redirect=0',
          which resolved against the host root and 404'd on every
          subdirectory install (e.g. https://host/moodle/...). They now
          build the URL via moodle_url('/', ['redirect' => 0]), which
          honours $CFG->wwwroot on any deploy layout.
        * block_onboarding.js setAttribute("src", avatarOption) on the
          user picture element used to set a host-root path
          (/local/profile/pix/avatars/...). On subdirectory installs the
          image silently 404'd. Now prefixed with Config.wwwroot so the
          preview matches what the server actually serves.
        * block_onboarding.js updateProfile() was building the AJAX URL
          by string concatenation with hand-coded encoding (only spaces
          were escaped). This had three concrete problems:
            - Hire dates with slashes and any non-ASCII name corrupted
              the URL.
            - The user's password was sent in the GET query string and
              therefore landed in browser history, Apache/Nginx access
              logs and every reverse-proxy log on the way.
            - Long names + long avatar paths could push URLs past the
              8KB ceiling some proxies impose on GET requests.
          Replaced with a POST + jQuery data object, which encodes every
          value correctly and never leaks credentials through URLs.
        * updateprofile.php reads via optional_param() (accepts GET or
          POST) so no server-side change was required.
